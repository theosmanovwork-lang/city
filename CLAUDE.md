# ASCII City

Сюжетная игра для Steam от первого лица в американском мегаполисе (дух Нью-Йорка
и Чикаго), где **вся графика состоит из текстовых символов**. Обычный современный
город — не киберпанк и не фантастика. Не открытый мир: прохождение локаций одна
за другой с упором на сюжет, по типу The Last of Us.

Вдохновение по технологии и визуалу — «ASCII City» от Grow Now! Games
(Rust + WebAssembly, вывод через WebGL, сетка ~180×80). Как и у автора, **никаких
3D-моделей и Blender**: вся геометрия описывается кодом и параметрами.

**Главная визуальная цель:** максимальная детализация — до грани, где символы
почти превращаются в пиксели, но стиль ещё читается как текст.
Ориентиры плотности (клетка 4×6 физических пикселей): 480×180 символов на 1080p,
640×240 на 1440p, 960×360 на 4K, при 60 FPS.

## Эталон

- `reference/ascii-city-v0.2.html` — рабочий прототип на JS/WebGL, **визуальный
  эталон и справочник по алгоритмам**. Никогда не изменять и не удалять.
- `reference/ascii-city-v0.1.html` — более ранний прототип (canvas 2D), исторический.

Эталон сделан в стиле киберпанка и на raycasting по карте высот. Из него берём
**стиль символов и приёмы шейдинга** (рампа, bgFill, bloom, LOD текста, детали фасадов);
raycasting и процедурный город **не переносим** (см. решения ниже);
тематику (неон, рекламные экраны с бегущей строкой, летающие машины, вечная ночь
под дождём) **не переносим**.

Что в эталоне есть по технике:
- Вывод: сетка ячеек (индекс глифа, цвет символа, цвет фона) → 3 текстуры; один
  полноэкранный фрагментный шейдер берёт маску глифа из атласа и смешивает bg/fg.
- Сцена: raycasting по столбцам (DDA по тайлам), фасады спереди назад с окклюзией,
  затем земля (floor casting), затем screen-space отражения в мокром асфальте,
  затем спрайты (billboard + буфер глубины).
- Стиль ячейки: ячейка получает реальный цвет освещённой поверхности; ЯРКОСТЬ →
  плотность символа (рампа), ОТТЕНОК → цвет символа (нормализован), фон ячейки
  слегка подсвечивается тем же цветом (bgFill). Функции `writeCell`, `rampG`.
- Свет: карта освещения 4 ячейки на тайл (фонари и витрины статично, фары
  динамически), bloom на уровне ячеек, туман по расстоянию.
- LOD текста: вывески вблизи — пиксельным шрифтом 5×7 из символов, на средней
  дистанции — одним символом в центре буквы, издалека — цветом.
- Детали фасадов по стилям: окна с рамами, шторы, жалюзи, силуэты, ТВ; балконы,
  кондиционеры, кирпич, стеклянные башни, витрины, вывески; крыши: антенны,
  водонапорные баки, билборды.
- Город процедурный и зациклен; машины со светофорами и дистанцией, пешеходы,
  дождь, облака, луна, звёзды.

## Игра: дизайн (решения владельца)

- **Сюжет и сцены.** Мир небольшой, открытого мира нет. Игра — последовательность
  сцен-локаций, каждая собирается отдельно (не процедурный город). Сцены включают
  **интерьеры**: квартиры, подъезды, магазины, метро.
- **Реализм.** Реальный масштаб: рост героя ~1.75 м (глаза ~1.65 м), этаж 3–3.5 м,
  ширина улиц и тротуаров как в жизни. Реалистичная скорость: шаг ~1.4 м/с,
  бег ~3.5 м/с (подбирается по ощущению). Дальность прорисовки близкая к реальной
  (туман, дымка, сама сцена ограничивают обзор).
- **HUD минимальный.** Диалоги — короткие кинематографичные субтитры внизу экрана.
- **Язык:** пока только русский (нужна кириллица в шрифтах).
- **Погода** разнообразная, но задаётся сюжетом сцены (дождь, снег, туман…).
  Время суток тоже задаётся сценой.
- **Машины** — одна модель, отличаются только цветом.
- **Пешеходы** — мужчины и женщины, отличаются причёской и одеждой.
- **Уличные мелочи** (гидранты, таблички, паркоматы, пар из люков…) прорабатываются
  на отдельных сценах, по мере надобности.
- **Облик города:** даунтаун со стеклянными башнями, ар-деко с уступами, офисными
  башнями, шпилями с красными огнями; кирпичные дома 4–6 этажей с пожарными
  лестницами и водонапорными баками; жёлтые такси, светофоры, WALK / DON'T WALK,
  маркизы над магазинами, дайнеры, дели, аптеки, прачечные, бары (неон — редкий
  акцент). Днём солнце и тени, вечером тёплые окна и фонари.

## Принятые архитектурные решения (не пересматривать без согласия владельца)

- **Язык:** Rust. Нативная программа для Windows/Mac/Linux (цель — Steam, включая
  Steam Deck 1280×800). Позже из того же кода — веб-сборка через WebAssembly.
- **Графика:** wgpu (шейдеры WGSL). **Окно и ввод:** winit. **Геймпады** позже: gilrs.
  Без игровых движков (никакого Bevy, Fyrox, macroquad).
- **Без 3D-моделей.** Геометрия — параметрические объекты, описанные кодом
  (дом = коробка с этажами, окнами, выступами; человек и машина — из простых форм).
- **Рендер сцены: ray marching по SDF на GPU** (решено вместо raycasting эталона,
  т.к. нужны интерьеры, нависания, объёмные люди и машины). Луч на каждую ячейку
  сетки символов → цвет/глубина → правило стиля → символы. Всё на GPU в compute-шейдерах.
- **CPU-параллелизм:** rayon — там, где понадобится (подготовка сцены и т.п.).
- **Steam:** crate steamworks (последний этап).
- Актуальные стабильные версии crates.

## Правила стиля (обязательны на всех этапах)

1. Сетка символов фиксированная, моноширинная; ячейки целого размера в ФИЗИЧЕСКИХ
   пикселях (с учётом DPI), без фильтрации (только nearest), без дробного масштаба.
2. Собственный пиксельный шрифт, нарисованный попиксельно (не системный).
3. Зазор между ячейками (по умолчанию 1 px, тёмный) — главный приём, отличающий
   ASCII от пиксель-арта. На увеличенных пресетах зазор растёт вместе с глифом
   (`gap_scales_with_glyph = true`).
4. Яркость → плотность символа, оттенок → цвет символа, фон — слабая подсветка;
   на самых мелких ячейках подсветка фона плавно уходит в 0 (`bg_fade_cell_h`).
5. Реалистичная сдержанная палитра американского города: кирпич, бетон, известняк,
   стекло, сталь, асфальт, зелень парков; тёплые окна и фонари вечером, естественное
   небо днём. Яркие цвета — только акценты (такси, вывески, светофоры, огни).
6. Визуальная проверка — сравнение с `reference/ascii-city-v0.2.html` по плотности
   и качеству (не по тематике). Скриншоты этапов — в `docs/screenshots/`.

Старая дорожная карта (процедурный открытый город на raycasting, расчёт ячеек
на GPU отдельным этапом) отменена решениями владельца после этапа 1. Отдельный
этап «люди и машина» заменён: люди и машина появляются в локациях по мере надобности.

### Итоги этапа 1
- Пресеты: 3×5 (клетка 4×6), 4×6 (5×7), 5×8 (6×9), 5×8 ×2 (12×18), 5×8 ×3 (18×27).
  На 1920×1080: 480×180, 384×154, 320×120, 160×60, 106×40 ячеек.
- Расчёт тестовой сцены на CPU в одном потоке (release): 3×5 — ~3 мс на 1080p,
  ~5 мс на 1440p, ~12 мс на 4K. На GPU каждый кадр уходят только 3 текстуры сетки.
- Проверено в контейнере: `--screenshot` (программный Vulkan llvmpipe) и запуск окна
  под Xvfb (75 FPS на llvmpipe). Реальные 60 FPS на полноэкранном 4×6 проверяет
  владелец на своей машине.

### Итоги этапа 2
- Ray marching по SDF на GPU (compute, `march.wgsl`): луч на ячейку (на крупных
  пресетах 2–4 по стороне), сетка ускорения 2 м, дальний силуэт отдельным списком.
  Правило стиля выполняется прямо в шейдере — CPU шлёт только параметры кадра.
- Свет: солнце/луна с мягкими тенями, видимость неба (2 луча) + отражённый свет,
  AO, до 16 ближайших точечных источников с тенями, туман, экспозиция по времени
  суток (днём ниже, ночью выше — «адаптация глаза»).
- Тестовая сцена «Тестовая улица» (559 форм): кирпичные дома с пожарными лестницами,
  крыльцами и водонапорными баками, дайнер с залом (стойка, табуреты, кабинки, лампы),
  известняковое здание, стеклянная башня на подиуме, перекрёсток, силуэт даунтауна.
- Игрок: глаза 1.65 м, шаг 1.4 м/с, бег 3.5 м/с, коллизии по SDF (3 сферы),
  ступени до 0.32 м, гравитация, покачивание камеры. Тесты движения — в `player.rs`.
- Субтитры отдельным слоем (5×8 ×round(h/540)), с плавным появлением и плашкой;
  триггеры-зоны в сцене. Кириллица в шрифтах 4×6 и 5×8.
- Проверено в контейнере: скриншоты (llvmpipe, 0.5–1.5 с на кадр — программный GPU)
  и окно под Xvfb (мышь, клавиши, HUD). Реальная скорость на видеокарте — проверяет
  владелец (F3 показывает FPS).
- Ограничения: стёкол нет (проёмы + невидимые препятствия), вывески без текста,
  нет bloom, тени от точечных источников только для 16 ближайших.

### Локация 1 «Сон. Переулок» (`src/scenes/dream_alley.rs`)
Сон героя: тёмный переулок ~3 м шириной, позади в 5 м — стрелок, впереди фонарь.
- Шагом фонарь не приближается; на бегу стены сходятся к концу, последние 3 м —
  проход 0.74 м (плечи впритык), время замедляется до 0.32, виньетка, сужение обзора.
- У фонаря — засветка в белое, «Я проснулся.», сон заново (следующей сцены пока нет).
- Стоять > 9 с, идти шагом > 30 м, пятиться к стрелку, остановиться на бегу > 2.5 с —
  выстрел (вспышка), чернота, сон заново («Снова этот сон.»).
- Сюрреализм: стрелок всегда в 5 м позади; окна у земли; двери на высоте второго этажа;
  мусор и лестницы уходят в стены, когда стены сходятся; огромная луна над фонарём.
- Движок: подвижные формы (габариты движения для сетки ускорения, обновление форм на
  GPU каждый кадр), капсулы и параметрический человек (`Builder::person`: пол,
  причёска, одежда, поза), сценарий сцены (`logic.rs`: состояния, эффекты `Fx`,
  перезапуск), второй compute-проход: свечение на уровне ячеек (bloom), виньетка,
  вспышка, затемнение и засветка, затем правило стиля.
- Тесты сценария (`app.rs`): добегает до света без выстрела и протискивается; выстрел
  при бездействии и при шаге назад; шагом фонарь не приближается.
- В тестовую улицу добавлены официантка и двое посетителей (проверка людей).

## Открытые вопросы

- **Следующая локация после сна:** сюжет — за владельцем.
- **Звук:** музыка, шаги, город, диалоги с озвучкой или без — обсудить до этапа 6.
- **Геймплей:** что делает игрок, кроме ходьбы и диалогов (взаимодействие с
  предметами, двери, выборы в диалогах) — обсудить до этапа 6.
- **Дневной контраст** (этапы 1–2): днём фасады в тени улицы и небо близки по яркости,
  картинка «серая». План: автоэкспозиция по яркости кадра и контуры (этап 4).
- **Производительность SDF на слабых GPU** (Steam Deck): узнаем после замера на
  видеокарте; рычаги — число лучей теней, дальность, шаги луча, размер сетки ускорения.

## Идеи на потом

- Шрифт 3×5: буквы M/N/W и `0`/`O` на этом размере различимы плохо — для UI
  использовать 4×6 и крупнее, 3×5 — только для сцены.
- Выбор пресета по умолчанию по размеру экрана и DPI (Steam Deck → 4×6 или 5×8).
- Описание сцен в файлах данных (RON) вместо кода — когда сцен станет много.
- Клавиша для переключения vsync (сейчас `Config::vsync`).
- Экспозиция кадра (автоэкспозиция) как часть правила стиля, а не тестовой сцены.
- Текст на вывесках из атласа шрифтов с LOD (как в эталоне): вблизи — пиксельные буквы.
- Стёкла витрин: полупрозрачность (второй луч сквозь стекло) и отражения.
- Замер времени кадра на GPU (timestamp queries) в HUD.
- Сцены в файлах данных (RON), когда сцен станет много.

### Как устроен вывод
- Сетка → 3 текстуры: глиф `R16Uint`, fg и bg `Rgba8Unorm`. Атлас всех шрифтов —
  одна `R8Unorm` текстура, шрифты друг под другом, глифы без масштаба.
- Шейдер: пиксель → ячейка (`cell = glyph*scale + gap`), внутри — зазор (правая
  колонка и нижняя строка) или маска глифа `atlas[slot*glyph + in/scale]`.
  Сэмплеров нет вообще, только `textureLoad` — фильтрация невозможна.
- Альфа фона: `0` — подсветка, умножается на bgFill (клавиша B); `255` — сплошная
  плашка (HUD), рисуется как есть.
- Вывод в не-sRGB формат поверхности (значения как в WebGL-эталоне); если доступен
  только sRGB — шейдер переводит в линейные (`srgb_out`).
- Слои: рендерер рисует несколько сеток в разные прямоугольники (scissor) —
  так сделан экран шрифтов (F1).

## Команды

```bash
cargo run --release                       # игра (локация 1 «Сон. Переулок»)
cargo run --release -- --scene street     # тестовая улица
cargo test                                # тесты (шрифты, сетка, SDF, субтитры, движение игрока)
cargo clippy --all-targets -- -D warnings # должно быть без предупреждений
cargo fmt
# скриншоты без окна (работает и на программном GPU):
cargo run --release -- --screenshot shot.png --preset 4x6 --time 0.8
cargo run --release -- --screenshot shot.png --camera 12.5,0.15,17.2,40,-4 --say "ИМЯ|Реплика"
cargo run --release -- --screenshot fonts.png --fonts
# флаги: --preset all|3x5|4x6|5x8|5x8x2|5x8x3|<номер>, --time 0..1 (0.5 — полдень),
#        --camera x,y,z,yaw°,pitch° (ноги игрока), --size WxH, --say "ИМЯ|текст",
#        --hud, --fonts, --no-gap, --no-bg, --scene alley|street,
#        --sim run:8,walk:2,idle:1,back:1,turn:1 (прогнать сценарий перед снимком)
```

Управление: щелчок — захватить мышь · WASD — идти · мышь — смотреть · Shift — бег ·
`Esc` — отпустить мышь (второй раз — выход) · `F3` — HUD · `+`/`-` плотность ·
`G` зазор · `B` подсветка фона · `[` `]` — час назад/вперёд · `T` — ход времени ·
`F1` — экран шрифтов · `F11` — полный экран.

Linux: нужны системные библиотеки X11/Wayland (`libxkbcommon-x11-0` и др.).
Под Xvfb без оконного менеджера окну нужно явно передать фокус (`xdotool windowfocus`).

## Правила работы

- Сначала показать план этапа (структура файлов, crates, ключевые решения)
  и дождаться «ок» владельца, потом писать код.
- Делать только текущий этап. Идеи для следующих — в «Идеи на потом», не реализовывать.
- Если что-то неясно или есть выбор, влияющий на стиль, — спросить, а не угадывать.
- В конце этапа: кратко что сделано, как запустить, что проверить глазами;
  обновить статус этапа в этом файле.
- Перед коммитом: `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, `cargo test`.
- Комментарии в коде и этот файл — на русском.
