# ASCII City

Игра для Steam: исследование большого американского города от первого лица,
где **вся графика состоит из текстовых символов**. Обычный современный город —
не киберпанк и не фантастика: даунтаун с множеством небоскрёбов, сетка улиц
и авеню, жилые кварталы, транспорт, люди. Атмосфера — узнаваемый мегаполис
в духе Нью-Йорка и Чикаго.

Вдохновение по технологии и визуалу — «ASCII City» от Grow Now! Games
(Rust + WebAssembly, вывод через WebGL, сетка ~180×80, raycasting).

**Главная визуальная цель:** максимальная детализация — до грани, где символы
почти превращаются в пиксели, но стиль ещё читается как текст.
Ориентиры плотности (клетка 4×6 физических пикселей): 480×180 символов на 1080p,
640×240 на 1440p, 960×360 на 4K, при 60 FPS.

## Эталон

- `reference/ascii-city-v0.2.html` — рабочий прототип на JS/WebGL, **визуальный
  эталон и справочник по алгоритмам**. Никогда не изменять и не удалять.
- `reference/ascii-city-v0.1.html` — более ранний прототип (canvas 2D), исторический.

Эталон сделан в стиле киберпанка. Из него берём **технику и стиль символов**;
тематику (неон, рекламные экраны с бегущей строкой, летающие машины, вечная ночь
под дождём) **не переносим**.

Что в эталоне есть по технике:
- Вывод: сетка ячеек (индекс глифа, цвет символа, цвет фона) → 3 текстуры; один
  полноэкранный фрагментный шейдер берёт маску глифа из атласа и смешивает bg/fg.
- Сцена: raycasting по столбцам (DDA по тайлам), фасады спереди назад с окклюзией,
  затем земля (floor casting), затем screen-space отражения в мокром асфальте,
  затем спрайты (billboard + буфер глубины).
- Стиль ячейки: ячейка получает реальный цвет освещённой поверхности; ЯРКОСТЬ →
  плотность символа (рампа), ОТТЕНОК → цвет символа (нормализован), фон ячейки
  слегка подсвечивается тем же цветом (bgFill). Функции `writeCell`, `rampG`.
- Свет: карта освещения 4 ячейки на тайл (фонари и витрины статично, фары
  динамически), bloom на уровне ячеек, туман по расстоянию.
- LOD текста: вывески вблизи — пиксельным шрифтом 5×7 из символов, на средней
  дистанции — одним символом в центре буквы, издалека — цветом.
- Детали фасадов по стилям: окна с рамами, шторы, жалюзи, силуэты, ТВ; балконы,
  кондиционеры, кирпич, стеклянные башни, витрины, вывески; крыши: антенны,
  водонапорные баки, билборды.
- Город процедурный и зациклен; машины со светофорами и дистанцией, пешеходы,
  дождь, облака, луна, звёзды.

## Каким должен быть наш город (этап 2 и дальше)

- **Планировка:** прямоугольная сетка, как на Манхэттене — длинные кварталы
  (~3:1), широкие авеню и более узкие улицы, переулки с мусорными баками.
- **Даунтаун:** МНОГО небоскрёбов, плотная застройка, силуэт виден издалека.
  Типы: стеклянные башни; ар-деко с уступами (setbacks) и коронами; офисные башни
  с сеткой окон; шпили и антенны с красными авиационными огнями.
  Небоскрёб = подиум + башня (+ уступы): высота может меняться внутри участка.
- **Ближе к окраинам даунтауна:** кирпичные дома 4–6 этажей (brownstones,
  walk-ups) с пожарными лестницами, водонапорные баки на крышах.
- **Улица:** жёлтые такси, автобусы, грузовики доставки, припаркованные машины;
  светофоры на кронштейнах и растяжках, сигналы WALK / DON'T WALK; гидранты,
  почтовые ящики, газетные автоматы, паркоматы, зелёные таблички с названиями
  улиц, маркизы над магазинами, входы в метро, пар из люков.
- **Первые этажи:** дайнеры, дели, аптеки, прачечные, бары — обычные вывески,
  неон только как редкий акцент (например, в барах).
- **Время суток:** полный цикл. Днём — солнце, тени от небоскрёбов, голубое небо,
  отражения в стёклах башен; вечером — тёплые окна, фонари, фары; ночью — огни
  небоскрёбов на силуэте.

## Принятые архитектурные решения (не пересматривать без согласия владельца)

- **Язык:** Rust. Нативная программа для Windows/Mac/Linux (цель — Steam, включая
  Steam Deck 1280×800). Позже из того же кода — веб-сборка через WebAssembly.
- **Графика:** wgpu (шейдеры WGSL). **Окно и ввод:** winit. **Геймпады** позже: gilrs.
  Без игровых движков (никакого Bevy, Fyrox, macroquad).
- **CPU-параллелизм:** rayon (этап 2). Позже расчёт ячеек — в compute shader (этап 4).
- **Steam:** crate steamworks (этап 7).
- Актуальные стабильные версии crates.

## Правила стиля (обязательны на всех этапах)

1. Сетка символов фиксированная, моноширинная; ячейки целого размера в ФИЗИЧЕСКИХ
   пикселях (с учётом DPI), без фильтрации (только nearest), без дробного масштаба.
2. Собственный пиксельный шрифт, нарисованный попиксельно (не системный).
3. Зазор между ячейками (по умолчанию 1 px, тёмный) — главный приём, отличающий
   ASCII от пиксель-арта. На увеличенных пресетах зазор растёт вместе с глифом
   (`gap_scales_with_glyph = true`).
4. Яркость → плотность символа, оттенок → цвет символа, фон — слабая подсветка;
   на самых мелких ячейках подсветка фона плавно уходит в 0 (`bg_fade_cell_h`).
5. Реалистичная сдержанная палитра американского города: кирпич, бетон, известняк,
   стекло, сталь, асфальт, зелень парков; тёплые окна и фонари вечером, естественное
   небо днём. Яркие цвета — только акценты (такси, вывески, светофоры, огни).
6. Визуальная проверка — сравнение с `reference/ascii-city-v0.2.html` по плотности
   и качеству (не по тематике). Скриншоты этапов — в `docs/screenshots/`.

| 2 | Мир и raycasting из эталона на Rust, rayon | ⏳ следующий |

- **Этап 1 — Каркас и рендер сетки символов на wgpu.**
- **Этап 2 — Перенос мира и raycasting из эталона на Rust**, расчёт столбцов на всех
  ядрах (rayon). Город по описанию выше: сетка авеню и улиц, небоскрёбы с подиумами
  и уступами (переменная высота внутри участка), кирпичные дома, цикл дня и ночи
  (солнце и тени днём, фонари и окна вечером). Дальность прорисовки — достаточная для
  силуэта небоскрёбов. Цель: плотность и качество как в эталоне, 60 FPS при 480×180
  на 1080p.
- **Этап 3 — Стиль на грани:** выбор символа по контуру (Собель по глубине и яркости →
  `/ \ | - _` на краях, рампа внутри), автоприглушение фона, переключатель клавишей
  для сравнения.
- **Этап 4 — Расчёт ячеек на GPU** (compute shader). Цель: 960×360 на 4K при 60 FPS.
- **Этап 5 — Геймплей** (обсудим отдельно: цель, задания, прогресс).
- **Этап 6 — Геймпад, Steam Deck, меню, настройки плотности и графики.**
- **Этап 7 — Steamworks:** достижения, облачные сохранения; веб-демо.

### Итоги этапа 1
- Пресеты: 3×5 (клетка 4×6), 4×6 (5×7), 5×8 (6×9), 5×8 ×2 (12×18), 5×8 ×3 (18×27).
  На 1920×1080: 480×180, 384×154, 320×120, 160×60, 106×40 ячеек.
- Расчёт тестовой сцены на CPU в одном потоке (release): 3×5 — ~3 мс на 1080p,
  ~5 мс на 1440p, ~12 мс на 4K. На GPU каждый кадр уходят только 3 текстуры сетки.
- Проверено в контейнере: `--screenshot` (программный Vulkan llvmpipe) и запуск окна
  под Xvfb (75 FPS на llvmpipe). Реальные 60 FPS на полноэкранном 4×6 проверяет
  владелец на своей машине.

## Открытые вопросы (решить перед этапом 2)

- **Погода и сезоны:** дождь, снег, туман; смена сезонов или один.
- **Размер мира:** зацикленный город (как в эталоне) или конечный с границами
  (река, залив, окраины).
- **Дневной контраст** (найдено на этапе 1): днём небо и фасады близки по яркости,
  и на крупных пресетах силуэт различается в основном оттенком. Варианты:
  экспозиция/тонмаппинг по времени суток (в тестовой сцене уже есть простая
  экспозиция), контуры этапа 3, более тёмные фасады в тени.

## Идеи на потом

- Кириллица в шрифтах (для русского UI): индексы глифов уже `u16`, символы
  добавляются в конец `font::EXTRA`. Пока весь текст на экране — латиницей.
- Шрифт 3×5: буквы M/N/W и `0`/`O` на этом размере различимы плохо — для UI
  использовать 4×6 и крупнее, 3×5 — только для сцены.
- Выбор пресета по умолчанию по размеру экрана и DPI (Steam Deck → 4×6 или 5×8).
- Клавиша для переключения vsync (сейчас `Config::vsync`).
- Экспозиция кадра (автоэкспозиция) как часть правила стиля, а не тестовой сцены.

## Структура папок

```
Cargo.toml, rustfmt.toml
src/
  main.rs        окно (winit), цикл с фиксированным шагом, клавиши, режим --screenshot
  app.rs         состояние без окна: пресеты, переключатели, время, HUD, экран шрифтов
  config.rs      все настройки (struct Config) — никаких магических чисел в коде
  font.rs        три пиксельных шрифта (битмапы в коде), рампы, атлас
  grid.rs        сетка: glyph u16, fg RGBA8, bg RGBA8; put / text / fill_rect
  style.rs       правило стиля: цвет → (символ рампы, нормализованный fg, bg)
  renderer.rs    wgpu: текстуры сетки, атлас, один пайплайн, offscreen-рендер
  scene.rs       тестовая сцена этапа 1: небо с циклом суток, силуэт небоскрёбов
  shaders/grid.wgsl  полноэкранный треугольник, textureLoad, mix(bg, fg, mask), зазор
reference/       эталоны (не трогать)
docs/screenshots/stage1/  скриншоты всех пресетов: день, закат, ночь, экран шрифтов
```

### Как устроен вывод
- Сетка → 3 текстуры: глиф `R16Uint`, fg и bg `Rgba8Unorm`. Атлас всех шрифтов —
  одна `R8Unorm` текстура, шрифты друг под другом, глифы без масштаба.
- Шейдер: пиксель → ячейка (`cell = glyph*scale + gap`), внутри — зазор (правая
  колонка и нижняя строка) или маска глифа `atlas[slot*glyph + in/scale]`.
  Сэмплеров нет вообще, только `textureLoad` — фильтрация невозможна.
- Альфа фона: `0` — подсветка, умножается на bgFill (клавиша B); `255` — сплошная
  плашка (HUD), рисуется как есть.
- Вывод в не-sRGB формат поверхности (значения как в WebGL-эталоне); если доступен
  только sRGB — шейдер переводит в линейные (`srgb_out`).
- Слои: рендерер рисует несколько сеток в разные прямоугольники (scissor) —
  так сделан экран шрифтов (F1).

## Команды

```bash
cargo run --release                       # окно
cargo test                                # тесты (шрифты, рампы монотонны, сетка)
cargo clippy --all-targets -- -D warnings # должно быть без предупреждений
cargo fmt
# скриншоты без окна (работает и на программном GPU):
cargo run --release -- --screenshot shot.png --preset all --time 0.95 --size 1920x1080
cargo run --release -- --screenshot fonts.png --fonts
# флаги: --preset all|3x5|4x6|5x8|5x8x2|5x8x3|<номер>, --time 0..1 (0.5 — полдень),
#        --size WxH, --fonts, --no-gap, --no-bg
```

Клавиши: `+`/`-` плотность · `G` зазор · `B` подсветка фона · `F1` экран шрифтов ·
`F11` полный экран · `T` ускорить время ×10 · `Space` пауза времени · `Esc` выход.

Linux: нужны системные библиотеки X11/Wayland (`libxkbcommon-x11-0` и др.).

## Правила работы

- Сначала показать план этапа (структура файлов, crates, ключевые решения)
  и дождаться «ок» владельца, потом писать код.
- Делать только текущий этап. Идеи для следующих — в «Идеи на потом», не реализовывать.
- Если что-то неясно или есть выбор, влияющий на стиль, — спросить, а не угадывать.
- В конце этапа: кратко что сделано, как запустить, что проверить глазами;
  обновить статус этапа в этом файле.
- Перед коммитом: `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, `cargo test`.
- Комментарии в коде и этот файл — на русском.
